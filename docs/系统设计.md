## 2. 技术选型

| 层级 | 技术 | 理由 |
|---|---|---|
| 前端框架 | Next.js 16 + TypeScript | App Router，ISR，TypeScript 类型安全 |
| UI 组件 | shadcn/ui + Tailwind CSS | 开箱即用，美观，无需自定义 CSS |
| 图谱可视化 | react-force-graph-2d | 力导向图，开箱即用，支持交互 |
| LLM | 火山引擎 kimi-k2.6 | OpenAI 兼容协议，响应快 |
| Embedding | doubao-embedding-vision | 与 LLM 同平台，延迟低 |
| 向量检索 | 内存数组 + 余弦相似度 | 5h 时限，无需外部服务 |
| 持久化 | /tmp/*.json | Vercel 临时文件，够用 |
| 部署 | Vercel | 免费，一键部署，支持 Serverless |

## 3. 数据流

```
用户上传教材
    → Parser Agent（前端解析 PDF/MD/TXT/DOCX）
    → POST /api/textbooks → /tmp/textbooks.json
    → 用户点击「构建图谱」
    → Extractor Agent（并发调用 LLM，上限 5）
    → POST /api/extract → /tmp/kg-{id}.json
    → GraphView 渲染力导向图
    → 用户上传多本教材
    → Aligner Agent（embedding 召回 + LLM 二次判定）
    → POST /api/align → /tmp/aligned.json
    → CompressionStat 展示压缩比
    → 用户提问
    → RAG Agent（分块 → embed → 余弦 top-5 → LLM 回答）
    → POST /api/rag/query
    → 用户对话修改决策
    → Critic Agent（解析意图 → 调用工具）
    → POST /api/chat
```

## 4. API 接口一览

| 方法 | 路径 | 输入 | 输出 |
|---|---|---|---|
| GET | /api/health | - | { ok, status, env } |

## 5. 核心模块说明

### 5.1 Parser Agent

前端完成所有解析，绕开 Vercel 函数 10s 超时。
- PDF：pdfjs-dist + worker
- MD/TXT：正则切分章节
- DOCX：mammoth

### 5.2 Extractor Agent

- 输入：章节标题 + 章节文本（截断 6000 字）
- Prompt：要求输出 JSON，含 knowledge_points 和 relations
- 并发：手写信号量，上限 5
- Fallback：若 LLM 返回空，基于分句生成基础知识点

### 5.3 Aligner Agent

- Step 1：对所有 KP 的 `name + definition` 做 embedding
- Step 2：跨教材两两余弦相似度 > 0.85 的入候选
- Step 3：候选组喂 LLM 判定（merge/keep/remove + reason + confidence）
- Step 4：应用决策，重映射关系，计算压缩比

### 5.4 RAG Agent

- 分块：600 字窗口，80 字重叠，带 metadata
- 索引：batchEmbed（64 条/批）→ /tmp/vectors.json
- 查询：embed 问题 → 余弦 top-5 → 拼严格 Prompt → LLM 回答
- 引用：回答中必须标注 [《教材名》第X章 第X页]

### 5.5 Critic Agent

- System Prompt 声明可用工具：update_decision, list_decisions
- 用户输入 → LLM 判断是否需要调用工具
- 返回文字回复 + 可选 toolCall
- 前端解析 toolCall，刷新图谱
