# 需求分析

## 1. 问题背景

高校同一学科存在多本教材并行使用，内容大量重复。例如"数据结构与算法"有七八本主流教材，"排序算法"章节在每本书中重复出现，但表述不同。学生浪费时间重复阅读，教师难以评估交叉与缺失。

## 2. 核心子问题分解

### 2.1 知识点粒度定义

- **概念**：学科中的基本术语（如"静息电位"）
- **定理**：经过证明的命题（如"欧姆定律"）
- **方法**：操作步骤或算法（如"快速排序"）
- **现象**：可观察的事实（如"动作电位"）
- **其他**：不属于以上四类的补充内容

每个知识点提取：名称（短）、定义（≤80字）、类别、所在页码。

### 2.2 重复判定标准

1. **Embedding 召回**：对 `name + definition` 做 embedding，余弦相似度 > 0.85 的进入候选
2. **LLM 二次判定**：候选组喂给 LLM，由模型判断是 merge / keep / remove
3. **跨教材原则**：同一教材内部的知识点不对齐，只比较不同教材

### 2.3 教学连贯性保障

- 保留知识点间的关系（前置依赖、并列、包含、应用）
- 整合后检查关系图是否断裂：若某知识点被删除，检查是否有其他知识点依赖它
- 压缩比上限 30%，超出时优先保留高频和核心概念

### 2.4 压缩比计算方式

```
ratio = 整合后保留的知识点对应原文 chunk 总字数 / 所有教材原始总字数
```

在 UI 显眼处显示百分比 + 进度条，即使达不到 30% 也显示真实数字。

### 2.5 RAG 分块策略选择依据

- **窗口 600 字，重叠 80 字**：兼顾语义完整性和检索粒度
- 优先按 `。！？\n\n` 切分，保证 chunk 边界在句末
- 每个 chunk 必须携带 metadata：教材名、章节名、页码，用于引用标注

## 3. 用户场景

| 用户 | 场景 | 功能 |
|---|---|---|
| 学生 | 快速掌握学科核心 | 查看整合后的精华知识图谱 |
| 教师 | 评估教材覆盖度 | 跨教材对比 + 对话修改整合方案 |
| 教学管理者 | 决策课程资源 | 查看压缩比报告 + RAG 问答 |

## 4. 非功能需求

- 浏览器可访问，支持 1920×1080
- 5 小时内可完成开发
- 不使用数据库，文件系统持久化
